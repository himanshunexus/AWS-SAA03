## Objects and access

- S3 stores objects under keys in buckets. It is not a block disk or a general POSIX filesystem.
- Use IAM and bucket policies for access. Keep Block Public Access enabled unless public access is deliberately required.
- A presigned URL grants time-limited access using the signer's permissions. Authorize the requester before generating it.
- Multipart upload splits large transfers into parts that can upload and retry independently. Transfer Acceleration can help long-distance transfers; test its benefit for the workload.

## Storage-class decisions

| Access requirement | Candidate |
|---|---|
| Frequent access | Standard |
| Unknown changing access | Intelligent-Tiering; understand optional archive tiers |
| Infrequent but immediate access | Standard-IA or Glacier Instant Retrieval |
| Re-creatable data in one AZ | One Zone-IA when loss of that AZ is acceptable |
| Archive with delayed retrieval | Glacier Flexible Retrieval or Deep Archive |

## Protect and retain data

- Versioning preserves object versions; deletion can create a delete marker rather than erase every version.
- Lifecycle rules transition or expire data. Account for noncurrent versions and minimum storage charges. Expiration is asynchronous.
- Object Lock provides retention and legal holds. Compliance mode is stronger against deletion during retention than governance mode.
- Replication is not a substitute for a retention policy or independent backups; configure what replicates and how recovery works.
- SSE-KMS adds KMS policy and request considerations. Bucket Keys can reduce KMS request traffic for eligible workloads.

## Common mistakes

- Encryption does not grant access. IAM permission does not bypass a KMS key policy.
- A storage class with hours-long restore time does not meet an immediate-access requirement.
